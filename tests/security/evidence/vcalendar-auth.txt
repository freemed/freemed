5. Does the emitted body contain PHI-shaped content?
   No. The body is the vCalendar envelope only:
       BEGIN:VCALENDAR / VERSION:1.0 / PRODID:<provider name> / TZ:-07 / END:VCALENDAR
   `PRODID` carries the PROVIDER's name (the seeded verification provider), not a patient's.
   There are no event entries because `scheduler` is empty, and it cannot be populated in this
   harness: the scheduler_Insert trigger writes a patient_emr row (MODULE='scheduler',
   PATIENT=NEW.calpatient) and patient_emr.patient has a foreign key to `patient`, a pinned,
   currently empty table. Inserting one appointment therefore fails with
   "Cannot add or update a child row: a foreign key constraint fails (`freemed`.`patient_emr`,
   CONSTRAINT `patient_emr_ibfk_1` ...)" unless the pinned `patient` table is seeded, which is
   out of bounds for this task. Consequence for the advisory, stated conservatively: the
   endpoint is demonstrated to AUTHENTICATE on the digest alone and to emit that provider's
   calendar envelope; what a populated install would additionally disclose (calpatient,
   calprenote/calpostnote per appointment) is NOT demonstrated here and must not be reported as
   demonstrated.
   Two further pre-existing PHP 8.3 defects sit between this and a client-parseable calendar,
   both left alone as out of scope:
     * vCalendar.class.php:61 — "$buffer" is never initialised, so the E_WARNING is printed into
       the payload. With display_errors=On (this harness, and the stock php:8.3-apache image
       which ships no php.ini) the body opens with a warning line and a strict client would
       reject it; with display_errors=Off (php.ini-production) the payload would carry no
       warning line at all (inference from display_errors, not measured in this harness).
     * Physician.class.php:83 — strpos() is handed the whole degree row (array) instead of its
       text, so a provider whose phydegrees DOES resolve a degrees row dies with
       "strpos(): Argument #1 ($haystack) must be of type string, array given". The seeded
       provider deliberately has no degree reference, which is why the envelope above is emitted.
       Recorded for a follow-up; the authorised bounded guard did not extend to it.
