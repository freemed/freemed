PHASE C - lib/settings.php (the independent finding), measured on its own
  Apache, HEAD : GET /lib/settings.php -> status=200 bytes=0
  nginx,  HEAD : GET /lib/settings.php -> status=200 bytes=0
  classify     : the file on disk is 1459 bytes and defines DB_PASSWORD; a 200 with a 0-byte body is the
                 PHP handler EXECUTING it and printing nothing, NOT the source. So: reachable and
                 executed on both servers, source not disclosed there - an unauthenticated entrypoint to
                 a file that must never be one, and a credential disclosure on any layout where the PHP
                 handler does not cover the path. Verdict and the list of such layouts:
                 doc/DEPLOYMENT_HARDENING section 6.
  after        : GET /lib/settings.php -> status=403 on all four servers (PHASE B).
  note         : lib/settings.php is generated by install.php and is not in the repository; the served
                 copy is the harness's, outside the git tree.
